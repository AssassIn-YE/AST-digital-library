# 广应科数字图书馆（课程前端作品）

> 广州应用科技学院 · 数字图书馆静态站点演示  
> 本项目为本科前端课程作业，用网页模拟图书馆官网的常见入口与基础交互，**不是**学校正式业务系统。

---

## 项目简介

这是一个纯前端的「数字图书馆」站点。打开后先进入 DeepSeek 风格的门户页，再跳进图书馆首页，可以浏览资讯、阅读导赏、登记读者信息，以及在本地记录自己的阅读计划。

整体目标比较朴素：把课上讲的 **HTML 结构、CSS 布局与样式、JavaScript 交互** 串成一套能看、能点、能跑的页面；同时试着用 AI 辅助写代码和改样式，提高完成效率。

---

## 技术栈

| 技术 | 用在哪里 |
|------|----------|
| **HTML5** | 各页面结构、语义标签、表单与导航 |
| **CSS3** | 主题色、布局、动效、响应式；门户页单独一套样式 |
| **JavaScript（原生）** | 导航下拉、轮播、表单校验、书架增删改、门户提示 |
| **Bootstrap** | 栅格（`container` / `row` / `col`）、部分表单与按钮基础样式 |
| **localStorage** | 「我的书架」把待读 / 已完成列表存在浏览器本地 |

没有后端、没有数据库、没有登录服务器。读者登记只做前端校验；书架数据只存在当前浏览器里，换设备或清缓存就没了。

> 如果你记得「HTML + CSS + JS」，但总觉得还缺一块——那一块大概率是 **Bootstrap**（帮布局省事）和 **localStorage**（本地存数据）。

## 功能一览

| 页面 | 文件 | 做什么 |
|------|------|--------|
| 门户入口 | `index.html` | 智能体对话框占位 + 三个快捷入口 |
| 图书馆首页 | `home.html` | 轮播图、服务入口、本馆亮点介绍 |
| 资讯速递 | `list.html` | 公告 / 新书 / 活动类图文列表 |
| 阅读导赏 | `content.html` | 专题长文，介绍本馆定位与使用建议 |
| 我的书架 | `toDoList.html` | 添加阅读计划，待读 / 已完成切换 |
| 读者登记 | `register.html` | 用户名、密码、手机、邮箱等前端校验 |
| 本馆概况 | `group.html` | 馆情、地址、开馆时间、联系方式 |
| 站点说明 | `member1Work.html` | 作者信息与各页面入口导航 |
| 跳转页 | `portal.html` | 自动跳到 `index.html` |

公共脚本在 `js/main.js`，主站样式在 `css/style.css`，门户样式在 `css/portal.css`。

## 亮点（我觉得还行的地方）

1. **门户 + 馆内两层入口**  
   门户页做成偏对话产品的简洁风格，馆内页再走传统官网导航，页面之间跳转比较清楚。

2. **交互不只是「能点开」**  
   - 首页自动轮播 + 圆点切换  
   - 导航下拉菜单、手机端菜单按钮  
   - 滚动后顶栏样式变化  
   - 读者登记实时校验（正则）  
   - 书架增删、完成 / 移回，并用 `localStorage` 记住

3. **统一视觉**  
   主站用偏校园蓝的配色和卡片布局，多页共用同一套导航和页脚，看起来像「一整站」而不是零散 HTML。

4. **课程向但贴学校场景**  
   文案和信息尽量按广应科图书馆公开介绍来写（校训、双校区、开馆时间等），方便课堂展示。

## 还没实现 / 已知局限

说实话，很多「看起来像有」的功能其实只是壳子或演示：

- [ ] **图书馆智能体**（门户对话框）未接入任何大模型 API，提交后只提示「暂未接入」
- [ ] **读者登记不上传服务器**，校验通过也不等于真的开户
- [ ] **没有真实借还书、座位预约、数据库检索**
- [ ] **资讯 / 导赏内容是静态写死的**，不能后台发布
- [ ] **书架数据仅本地浏览器**，无账号同步
- [ ] **未做真正的用户登录态、权限、后端接口**
- [ ] 部分链接（如站点说明里的外部练习页）依赖本机其它文件夹，单独拷贝本项目时可能打不开

这些不是偷懒甩锅，而是课程范围以**前端静态站点**为主；后端和真实业务要另开项目才合适。

## 怎么本地打开

不需要安装 Node，也不用打包：

1. 解压 / 打开本文件夹  
2. 用浏览器打开 `index.html`（或 `home.html`）  
3. 推荐用 Edge / Chrome 看效果  

也可以在 VS Code / Cursor 里用 Live Server 之类插件起一个本地预览。

## AI 在这次开发里怎么用、起什么作用

我是本科生，很多细节（布局怎么写才整齐、正则怎么写、轮播怎么切）一开始写得慢，或者写出来一堆小 bug。这次开发里，AI 主要扮演的是 **「结对编程助手」**，而不是「替我交作业的人」。

### 我一般怎么用 AI

1. **先自己想清楚页面要干什么**（比如：登记页要校验哪些字段、书架要不要本地保存）  
2. **把需求用白话告诉 AI**（结构、样式大致方向、交互规则）  
3. **让它出一版 HTML / CSS / JS 草稿**，我再对着改文案、改颜色、对齐导航  
4. **卡住时把报错或「看起来不对」的现象丢回去**，让它帮排查（选择器写错、事件没绑上等）  
5. **让它帮忙统一多页导航、页脚和命名**，减少复制粘贴漏改  

### AI 具体帮过什么

- 搭页面骨架、统一导航栏和页脚结构  
- 写门户页（偏 DeepSeek 风格）的布局和基础交互提示  
- 补轮播、下拉菜单、表单校验、`localStorage` 书架逻辑  
- 调整 CSS（间距、响应式、滚动顶栏等）  
- 润色部分馆情介绍文案的组织结构（内容仍按公开信息核对）  

### AI **没有**替代的部分

- 选题、页面功能范围、要不要做智能体占位——还是自己定的  
- 最终代码要自己打开浏览器点一遍，改到能交差  
- 学号、作者信息、学校相关事实需要自己核对  
- 作业说明、答辩时讲「为什么这样设计」——必须自己能说清楚  

一句话：**AI 负责加速「写出来」和「改通」，我负责「做什么、做成什么样、以及能不能讲明白」。**
